# `@stable` orphans and ownership

> Moved verbatim from `CLAUDE.md` (#2532). `CLAUDE.md` keeps the standing rules and links here; this file keeps the mechanism, its history and its measurements. Counts and dates are as of when each passage was written. Re-measure before quoting one.

- **`stable-orphan-reconcile.yml`** — **Disabled since 2026-10-11, kept as the way back (`gh workflow enable stable-orphan-reconcile.yml`).** The reconcile runs on the QA VM as `e2e-routine-stable-orphans` (`ops/vm/run-stable-orphans.sh`, Mondays 10:00 UTC, #2224): the same `scripts/reconcile-stable-orphans.ts`, reading the open trackers of both repositories (`ORPHAN_TRACKER_REPOS`), with its report issue on the destination rather than here. Disabled after a rehearsal on the VM produced the same report as the workflow, before the routine's first scheduled run. The reconciler did not change in what it decides; it gained `--issues-file`, to read the trackers of more than one repository. What follows describes the mechanism. It ran weekly (Mon 09:00 UTC) + dispatch. Reconciles **`@stable` removals against the trackers that own putting the tag back** (#1746). The asymmetry it closes: removal is automatic and lands on `main` unreviewed, restoration is a checkbox on an issue — so an issue closing with that checkbox unticked leaves a test out of the daily forever with nobody holding it. Three hand audits found the same class (#974 → 8 tests, #1504 → 5, and #1460, caught only because a human happened to read the call sites). `scripts/reconcile-stable-orphans.ts` parses every declared test (`parseDeclaredTests` in `scripts/lib/stable-tests.ts` — the complement of the Phase 0 parser, so a test with **no** `tag` array is a row rather than an absence), keeps the non-`@stable` ones, walks each spec's git history until the **same title** carried the tag — which dates the removal and names the commit — then asks whether any **open** issue names the spec. Classification and rendering are pure in `scripts/lib/stable-orphans.ts`; both halves are covered by `npm run test:units`. **Five traps, each of which actually occurred in the hand audits.** *"Issue closed" is not the criterion — "no OPEN issue names it" is*: #1460 closed **with** the restore performed, so keying on the tracker's state reports false orphans; issues also get **reopened**, hence live state on every run and nothing cached. **Two states, not one** — the tag is stripped automatically by the daily while `test.fixme` is added by hand in a quarantine PR, so a test can be off the daily with the tag alone. (#1746 cites `32ac9a1` / `4be67e9` as four weeks apart; they are **one day** apart and the second names the first in its own comment — the rule stands on the two mechanisms being separate, not on that gap.) "Runs nowhere at all" is the worse state because only `test.fixme` also takes the spec off the PR impacted-specs lane: that lane selects by import graph and uses `@stable` as an **ordering, never a filter**, so removing the tag alone leaves the spec running and **red** there — which is what #871 was raised about. **Some absences are permanent and deliberate** (`groq`/`mistral`, #1039), so they are declarable in `scripts/lib/stable-orphan-exemptions.json` — and, per #1084, verified in **both** directions: a declaration whose test carries `@stable` again, was renamed, gained a lane tag, or never carried the tag at all is reported as expired rather than honoured. And **line numbers drift; titles do not** — every issue in #1504's table cited a line and two of five had moved, so the match key is the title and the line is display only. Two mechanical notes. The history walk reads **blob SHAs out of `git log --follow --raw`** rather than paths, which is what lets a moved spec keep its history and lets one `git cat-file --batch` fetch every revision. It runs over the **candidates only** — 100 non-`@stable` tests in **62** specs of the 815/314 the AST pass reads — measured **5.5–7 s** end to end including the issue lookup. It needs `fetch-depth: 0`, and that is checked rather than assumed: `git rev-parse --is-shallow-repository` decides whether "the walk ran out of revisions" means `never` or `UNKNOWN`, because a truncated history runs out long before any cap and every unresolved row would otherwise read as clean — measured on a real `--depth 1` clone before the check existed, **0 orphaned, 0 undecidable**, both live orphans gone and both valid #1039 declarations reported as expired. It is its own workflow and **not** a step in the daily's merge job — that job is shallow, commits the run history back to `main`, and is not worth deepening for a report whose state moves in weeks. And the report issue's title is emitted by the script and read by the workflow, never spelled twice, because the tracker matcher **excludes its own issue**: counting it would mark every orphan "owned" on the next run, empty the report, and bring the finding back the run after — an oscillation with no visible symptom, pinned structurally. **A second finding class ships in the same report (#1783):** a spec whose tests carry **no** `@stable` must say why, and nothing verified that the issue its prose cites is still **open** — `agent-tool-inspection` cited #818 for two weeks after #818 closed. Scope is what makes it buildable: #1451's proposed sweep for a gating construction over `docs/**` selects **149 lines across 85 files** (`787cd420`; 151 / 86 by `a2250fdb` — it counts our own prose and moves, so re-run the command in the module header rather than quoting it), overwhelmingly legitimate history, and still misses gates written without a gating verb; this reads only the two places `CONTRIBUTING.md` requires the justification to live (the doc's `## Tags` section, the Part II bullet) for the **54** spec files where no test is `@stable`, and takes precision from a declarations file (`scripts/lib/gate-justification-declarations.json`) rather than from a keyword list. **Every** cited reference must be closed for a row to be a finding — one open reference means the justification stands. A **`[x]`** checklist bullet is not a justification and is excluded: its references are coverage history, and counting them fails in the SILENT direction — Run Flow's `[x]` bullet claims *"`@stable` restored 2026-08-11 (#966)"* on a spec that carries no `@stable`, so one of its three history refs being reopened would have filed a genuinely dead gate as `live`. Four traps, each of which produced a wrong verdict first: an open issue **naming** the spec does **not** clear the row (it prints beside it as context) because suppressing on it reproduced the self-reference oscillation `ORPHAN_ISSUE_TITLE` exists to prevent — #1783 itself lists every affected spec and marked 10 of 11 rows owned; a bare `#N` that does not resolve here is **undecidable, never closed**, since this repo writes `#14512` for an upstream PR; `MERGED` counts as closed, most upstream refs cited being PRs; and reference matching accepts only the **two** slugs the prose measurably uses — 88 qualified citations, 80 `langflow-ai/langflow` and **8 `oriontech-me/langflow-e2e`**, our own repo written out, which an any-slug-is-upstream rule resolved against Langflow. Two `gh` behaviours are load-bearing and pinned: `gh api graphql` substitutes `{owner}` and `{repo}` but **not** `{name}` (which goes through verbatim), and it **exits non-zero on a partial resolution while still returning every alias that did resolve** — not an edge case, since the bare-`#14512` row produces it on every run. A reference that does not **exist** is a finding; one that could not be **asked** about is an outage, and `gate_lookup_failed` bars the refresh and the close for it, the way `tracker_lookup_failed` already does. **Warns, never fails**, and never as a log line (`mode=count`, #1252): the output is one issue kept current, which closes itself when there is nothing left; the job fails only when the RUN is broken (unreadable declarations file, empty spec parse), and every undecidable row — shallow clone, unreadable `tag` array, failed issue lookup — is reported `UNKNOWN` with its reason (#1012). Not a PR gate: a pre-existing orphan is not the author's fault (#980).

- **`@stable` ownership guard (#1770)** — `scripts/check-stable-ownership.ts` (`npm run check:stable-ownership`), verdict pure in `scripts/lib/stable-ownership.ts`. A spec whose tests carry **no** `@stable` runs in no scheduled lane, so it needs an **open** issue naming the file or a declared absence; nothing checked that until this, and the inherited-spec audit found 55 such specs with no owner. **The sibling of `stable-orphan-reconcile.yml`, not a copy of it**: #1746 asks who owns restoring a tag that was **removed**; this asks who holds a spec nobody is holding, whatever its history. They share their inputs on purpose — #1746's `fetchOpenIssues` + boundary-safe `buildSpecTrackerIndex`, and its `stable-orphan-exemptions.json` read per spec — so the two reports cannot disagree about one spec; the plan's draft second exemptions file and basename matcher were dropped as duplicates (measured before writing, recorded in the plan's Task 8). **Both report issues are excluded from both tracker searches** (`withoutReportIssues`, applied in the shared fetch and again in this CLI): a spec that loses its last `@stable` sits in both populations, so either report counted as a tracker would "own" what it lists — #1746's self-exclusion oscillation, in two directions. **Two lanes, severity by the diff (#980).** `pr-validation.yml`'s `checklist-guard` job runs it with `--base-ref`: the frozen triage baseline (`tests/assets/triage/inherited-backlog-baseline.json`) is read **from the base ref**, so regenerating it inside a PR cannot hide the spec it adds, and a spec outside that baseline **fails only when the PR touched it** — the daily strips `@stable` from a hard-failing test by itself, so a spec can leave the daily with no PR involved, and failing every later PR on it would invert #980; that case is a warning. The frozen baseline is **one** `::notice::` (GitHub keeps ten annotations of a kind per step and drops the rest silently); the table goes to the step summary. The job gained `permissions: {contents: read, issues: read}` because this workflow never read issues before and a 403 would make every row `unknown` — which fails, #1012 — on every PR. `daily-stable.yml` runs it as its **own job** (`stable-ownership`), not a `merge` step, on one measured fact: the issue lookup shells out to `gh` and the Playwright image `merge` runs in ships none. No `needs:` (it reads ASTs and live issues, so a green day and a red one are equally valid), job-level `continue-on-error`, and ONE standing `qa-infra` issue whose title comes from the script's output and is never spelled in YAML; refreshed only when the body changed, closed when nothing is left, left untouched on a lookup outage. `scripts/resolve-echo-endpoint.test.mjs`'s jq guard therefore names the host job instead of assuming every daily job is containerized — revisited explicitly, per that test's own instruction, and verified both ways. **Deliberately not built:** an `expired-exemption` rule keyed on "the cited issue is closed" — both real declarations cite #1039, which is closed and is provenance for a standing packaging policy; #1746 already verifies each declaration against the test's actual state. Measured when built: 32 backlog specs → 1 owned (#963), 2 declared, 29 unowned in the baseline, exit 0 on both lanes.
