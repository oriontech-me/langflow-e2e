# Infra exemptions for `@stable` removal and flake triage

> Moved verbatim from `CLAUDE.md` (#2532). `CLAUDE.md` keeps the standing rules and links here; this file keeps the mechanism, its history and its measurements. Counts and dates are as of when each passage was written. Re-measure before quoting one.

- **Which attempt the `@stable` exemption reads (#1589)** — the infra-signature exemption (#1031/#1310) classifies a hard failure from the **last** failed attempt, and `remove-stable-from-failures.ts` and `append-weekly-history.mjs` are documented as reading the same one so the umbrella and the history file cannot disagree. That rule was chosen against a **sustained** wedge, where retries are burnt and the final attempt decided the verdict — and it does not hold against an **intermittent** one, which cycles *through* the retry budget instead. On run 32827671203 shard 3 (the only red job) measured **156 of 894 probes down** across 15 windows as short as 6–8 s inside a 30 s budget, and **4 of the 7** hard failures carried a transport-level signature on an earlier attempt and lost it on the last — one of them the barrier's own `[backend-unreachable]` marker — so the run scored `exempt: 0, attributableFailures: 7` and the umbrella's collateral block rendered **empty** on a day 17.4 % of probes were down. It changed no outcome there (the mass-failure guard counts every hard failure, 7 > 5), but it decides the **sub-threshold** day, which is not rare (2026-08-04, 08-13, 08-17, 08-24 all ≤ 5), and it is the labelling a human triages from. An **earlier** attempt now exempts too, and only with **measured corroboration**: the in-run recorder must have measured an outage window overlapping *that attempt* on *its own shard*. The overlap is computed where it already lived — `report-backend-outages.mjs`'s `attribute()`, the only place that knows which shard a test ran on, since the merged report does not — and is handed over as `outage-attempts.json` (`OUTAGE_ATTEMPTS_OUT` → the action's `outage_attempts` input); the join key is `(spec, title, retry)` and both sides read **one** normaliser (`scripts/lib/spec-path.mjs`), because a near-miss there corroborates nothing, exempts nothing and is invisible. **Fail-closed everywhere**: absent, unreadable or malformed file, or a run whose shards produced no probes, all degrade to exactly the last-attempt rule — so the removal set stays a **subset** of the pre-#1031 script's, the invariant #1031 pins, and a caller with no recorder at all is unaffected. Two things it deliberately does **not** do. The corroboration widens **which attempt may be read, never which signatures qualify** — a measured outage does not make a `locator.click` timeout transport-level. And an earlier attempt that classifies with no corroboration is **not** exempted and **not** silent: it is reported as a `disagreement` naming the attempt, the signature and *why* it was declined, which keeps "we measured and this attempt did not overlap" apart from "nothing was measured" (#1012). The history file keeps the same split — `infra_signature` still reads the last attempt (the two scripts still agree), and `infra_signature_any_attempt` is additive, a **lead rather than a verdict** (it carries no corroboration), which is what lets a later triage recomputing recurrence see collateral the old field recorded as `null` — **no automation reads it yet**, `triage-core.mjs` still keys on `infra_signature` alone, and recording it now is what makes wiring it possible at all, since a field added later cannot backfill the rows being written every day. Branches 2 and 4 of the issue were weighed and declined in `remove-stable-from-failures.ts`'s header: unqualified any-attempt reading would exempt a regression that hit one blip on a retry, its "≥2 attempts classifying" qualifier does not solve the motivating run (all four cases had exactly one), and doing nothing leaves the sub-threshold day exposed.

- **What no signature can reach: the assertion-shaped failure inside a measured outage (#1763)** — the exemption above classifies the error TEXT, so it only ever sees a failure that *reports* the transport. A spec that wraps its wait in an assertion reports the **state that never arrived** — `expect(received).toBe(expected)`, `"de-AT": the application never reached its main page` — and that is most specs, so a wedge-caused failure of one classifies `null` on **every** attempt of **every** run. `actionable = recurrent && !infra_signature` then resolves to `true`, and the triage's response to an actionable flake is to remove `@stable` and add `test.fixme`: a `@release` spec quarantined for a backend outage, which is the harm #1031 was raised about arriving through the one door #1310 and #1589 both left open. **Widening the pattern list cannot close it** — the message is about the state, not the transport, and every pattern that would match it is excluded for the reason #1031 gives. Measured twice in three weeks, on two unrelated specs: `agent-system-prompt.spec.ts:213` (2026-09-08, both failing attempts 82 %/87 % inside outages on a shard whose five outage windows were 1:1 with five gunicorn `WORKER TIMEOUT`s, 41 % down) and `locale-resilience.spec.ts:116` (2026-09-10, 66 %, no model dependence at all to explain it away) — both declined by hand, each costing three runs' `results.json`, four `liveness-N` artifacts and four container logs. So the evidence comes from a **measurement** instead: `report-backend-outages.mjs` already computes per-shard per-attempt overlap, and since #1763 it also measures **how much** of the attempt's span was covered (`scripts/lib/outage-overlap.mjs` does the join; the appender writes `outage_overlap` on every failure and flake row). **The fraction is the instrument, and the boolean is not** — this repo's own honesty note says a touch is close to a coin flip on a shard 33–73 % down, and `collateral_attempts > 0` on 11 of the 15 days carrying a `backend` block, while 0.66–0.87 separates cleanly from the 0.046 of the 6-second blip the issue names as the case that must *not* exempt anything; `shard_down_pct` travels beside `min_coverage` so a reader has the base rate. Four properties. It is **`min`, not `max`**: one corroborated attempt beside one clean one is a test that failed while the backend was answering. The **signature keeps precedence** — an `ECONNREFUSED` is transport-level whatever the backend was doing, so `infra_excluded` renders and `outage_excluded` does not. `unmeasured`, `clear` and an absent block **all leave the flake actionable** (#1012), which is also why a caller with no recorder is untouched. And it is scoped to the **flake** path *only*: the quarantine is a human-confirmed proposal where `@stable` auto-removal is an unreviewed commit, so the overlap may demote a flake and is deliberately not wired into `remove-stable-from-failures.ts` — #1589's rule that a measured outage never makes a product assertion into a transport error stands exactly where it was. The threshold (0.5) lives with the consumer that acts on it, and **below it the flake stays actionable and still prints its `outage_overlap`**, so moving the knob never hides evidence, it only moves who decides. Recorded on the row rather than left in the artifact because `liveness-*` expires after 7 days against a 30-day recurrence window — `recurrence.outage_by_date` now names each earlier occurrence's state, with `unrecorded` as a fourth value for pre-#1763 rows, which is what kills "a later triage sees the same `actionable: true` with no trace of the earlier refutation". **Its join key is #1589's plus the provider variant**, and that difference is forced rather than tidy: a parameterized spec emits one `spec` per provider with the same file, the same `spec.title` and the same line, so a 3-part key lets one variant's outage answer for another's failure — tolerable for #1589, which also requires the error to classify and records the leniency, and not for a consumer deciding on the measurement alone. Five of the 55 committed history rows already carry a duplicate `(file, test)` pair, and the weekday rotation step is `continue-on-error` with multi-provider as its documented fallback; `scripts/lib/spec-param.mjs` is the one spelling both sides derive it from. Both lanes write it (`daily-stable.yml` and `scripts/run-e2e.sh`), so `compare-lane-verdicts.mjs` does not sit on a permanent UNVERIFIED. Covered by `npm run test:scripts` (the reporter's coverage maths, the join's three states, the appender's wiring) plus the triage pipeline's own `triage-core.test.mjs`.
