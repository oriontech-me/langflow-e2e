# Lane-selector and specialised tags

> Moved verbatim from `CLAUDE.md` (#2532). `CLAUDE.md` keeps the standing rules and links here; this file keeps the mechanism, its history and its measurements. Counts and dates are as of when each passage was written. Re-measure before quoting one.

## Cross-cutting

| Tag | When to apply |
|---|---|
| `@destructive` | Test mutates account-wide state (e.g. deletes every project of the shared superuser). **Lane selector, not a severity:** `playwright.config.ts` excludes it from every normal run via `grepInvert` and CI runs it alone afterwards with `PW_DESTRUCTIVE=1` (workers pinned to 1). Run it locally with `PW_DESTRUCTIVE=1 npx playwright test --grep @destructive`. **Scheduled since #2142**: the VM daily (`scripts/run-e2e.sh`, `E2E_LANES`) runs the tests carrying `@stable` **and** `@destructive` on shard 1's backend once that shard's `@stable` round is over, under `PW_DESTRUCTIVE=1`, and merges their blob into the day's report; the listing-completeness check covers the lane. Before #2142 nothing scheduled it, and `@stable` was barred from it (#1010) |
| `@enterprise` | Test targets a Langflow **Enterprise** instance, whose surface the OSS nightly does not serve. **Lane selector, not a severity**, resolved together with `@destructive` in `tests/fixtures/lane.ts`: the lane selectors are mutually exclusive (a count is deliberately not stated — it went stale when `@serving` was added), and the enterprise one also pins `workers: 1` because an Enterprise instance runs password-first — there is no `auto_login` — and Langflow rate-limits `/api/v1/login` per IP, so parallel workers exhaust the budget and report product assertions as `429`s. Point `PLAYWRIGHT_BASE_URL` at the instance and run `PW_ENTERPRISE=1 npx playwright test --grep @enterprise`. Do **not** combine with `@stable` — there is no scheduled Enterprise lane, so such a test would silently never run (#1010) |
| `@serving` | **Lane selector**, the third and the only PARALLEL one, resolved with the other two in `tests/fixtures/lane.ts`. Targets the **same OSS nightly image under a different configuration**: serving-plane end-user identity (upstream #14443/#14550) is off by default and turned on only by instance-global env vars, so the cross-user memory boundary is unreachable from every other lane and a spec gating on the settings would skip everywhere (#1010's green all-skip). Start it with `./scripts/start-langflow-serving-identity.sh`, which parameterises the **three** container states the contract needs — `TRUST=true` (identities isolate), `LANGFLOW_SERVING_TRUST=0` (fail-closed **and** fail-silent: every request becomes `anon::<uuid>` and persists **nothing**, so naming the header without trusting it disables chat memory instance-wide while runs still answer `200`) and `LANGFLOW_SERVING_REQUIRED=1` (an identity-less request, and a whitespace-only one, are refused `401 END_USER_IDENTITY_REQUIRED`). Then `PW_SERVING_IDENTITY=1 npx playwright test --grep @serving`. **Parallel is a decision, pinned by `lane.test.ts`**: neither cause that serialises the other two applies — the variant keeps `auto_login` (no login budget to exhaust) and isolation is keyed per `session_id`, so serialising would cost ~4× wall clock for nothing. Precedence when several flags are set is `@enterprise` > `@serving` > `@destructive`, by how specialised an instance each demands, announced rather than silent. **Scheduled since #2142**: the VM daily runs the tests carrying `@stable` **and** `@serving` after the shards, starting each of the three variants in turn on its own port over the run's own served artifact (not a Docker image), with each spec mapped to the variant it asserts in `scripts/lib/scheduled-lanes.mjs`. A spec mapped to no variant fails the run. Before #2142 `@stable` was barred from it (#1010). Measured on `1.12.0.dev37`/`dev38`; the four-configuration contract and the port-shadow trap the start script now fails on are in `docs/serving/end-user-identity-lane.md` |
| `@instance-migration` | **Lane selector**, the fourth, and **serial**: targets a SOURCE Langflow with instance migration (*Settings > Migration*, upstream 1.13+) turned on, plus the two destinations it copies into, and is **not** the schema-upgrade migration `e2e-routine-migration` covers (#2193). Nothing else reaches it: the routes mount only when `LANGFLOW_FEATURE_INSTANCE_MIGRATION=true` at process start, its pause answers `503` to every write outside `/api/v1/migration/`, and a SQLite source needs an EMPTY PostgreSQL + pgvector and an S3 bucket. Start it with `./scripts/start-langflow-instance-migration.sh` (three containers on one network, seeded flow + file + knowledge base), then `PW_INSTANCE_MIGRATION=1 npx playwright test --grep @instance-migration`; reset between tests with `resetInstanceMigration()` (`tests/helpers/instance-migration/`, ~2-4 s, against ~45 s for a fresh container per file). Serial because there is ONE migration record per instance and the pause is instance-global, pinned by `lane.test.ts`. Precedence `@enterprise` > `@instance-migration` > `@serving` > `@destructive`. Two premises the issue carried were false when measured on `1.14.0.dev14`: MinIO publishes no pullable image any more, so the bucket is SeaweedFS (upstream's own CI image), and the nightly lacks the `pgvector` package, so the source runs a derived image that adds exactly that. Do **not** combine with `@stable` — there is no scheduled lane (#1010). Contract and decisions in `docs/instance-migration/instance-migration-lane.md` |
| `@background-worker` | **Lane selector**, the fifth, and **serial** (#2574). Targets the same OSS image with the **database-backed background backend**: `LANGFLOW_BACKGROUND_BACKEND=scaled` (upstream #13508) makes `POST /api/v2/workflows` in `mode=background` only QUEUE the job in the database, and a separate `langflow worker` process on the same database lease-claims and runs it. The default in-process backend starts a job the moment its 202 returns, so a job held while no worker runs, cancelled while queued, or refused at start because its API key was deleted while it waited (`authorization_denied`, handed over from #2573) is unreachable from every other lane. Serial because the worker is ONE process the instance shares and the tests assert what happens to the queue around it. **Scheduled** in the VM daily (`E2E_LANES`): two variants on `LANE_PORT`, `queued` (no worker) and `worker` (one worker started by `scripts/start-langflow-worker.sh` on the instance's own state and database, ready once it registers in `worker_registry`). By hand: `scripts/start-langflow-source.sh` with the variable, then the worker starter. Measured on `1.14.0.dev39`: a job stays `queued` with no worker, a queued job cancels, a held job completes ~19 s after a worker starts (the worker's boot) and in ~1 s with one up; the worker takes ~870 MiB RSS beside a ~510 MiB API. Reading a FAILED job's status answers **500** `JOB_FAILED` with the cause in `error_detail` — upstream's design (`src/backend/base/langflow/api/v2/workflow.py`), so a spec asserting a failed job declares that 500 rather than reading it as a backend error. Not covered, by decision: dependency-ready DAG scheduling (#16432) and scheduler snapshot retention (#16433), which are `lfx` `Graph` parameters no server setting reaches, and the worker fleet metrics (#15790), which are OpenTelemetry gauges and a database table with no API |

## Functional

| Tag | Area |
|---|---|
| `@a2a` | Agent-to-Agent protocol — publishing a flow as an A2A agent (card, discovery, JSON-RPC) and consuming remote agents via the `A2AAgent` component. **Needs `LANGFLOW_A2A_ENABLED=true`** (set on every lane and both start scripts since #1240); with it off the whole surface answers 404 and these specs would pass while testing nothing, so they call `requireA2aEnabled()` first |
| `@authz` | Enterprise **authorization** — roles, assignments, shares, teams and the audit log. Always combined with `@enterprise`, and the one case where the plan's tag rule calls for a NEW functional tag rather than reusing an OSS one: the OSS authorization service is pass-through (`enforce()` returns True and says so in the log), so there is no OSS area to reuse. Needs the RBAC container variant — `LANGFLOW_EE_RBAC=1 ./scripts/start-langflow-enterprise.sh`, a second container with its own Postgres on port 7891 — because RBAC is a property of the database as much as of the process: the bootstrap writes role assignments at startup and there is no way back to an unenforced instance. Specs gate on `authz/status` reporting `authz_enabled: true` **and** `superuser_bypass: false`; the second half is the one that gets forgotten, since a bypass left on exempts the only account the lane has and a whole deny matrix would pass against an instance that never denied anything |
| `@evals` | **Evaluations** (upstream langflow-ai/langflow#15999, Langflow 1.14) — datasets (`/api/v1/datasets`), flow evaluations and their runs (`/api/v1/evaluations`, `/api/v1/evaluation-runs`) and the evals UI (the Datasets and Evaluations pages, the flow toolbar's Evaluate button). A **new** functional tag by the rule `@integrations` and `@authz` set: no OSS area fits — `@observability` is traces and tokens, `@files` is the file store. Not a lane selector: on by default since upstream #16591 (`GET /api/v1/config` → `feature_flags.evals: true`, measured on `1.14.0.dev38`). A spec gates on that flag through `readEvalsSurface()` (`tests/helpers/api/evals/datasets.ts`): an **absent** key skips (a build that predates evals), a **false** one fails, because the default is on and a green all-skip would hide it (#1010). Only the `llm_judge` scorer calls a model; a spec that uses it is provider-dependent (#1216) and carries a provider tag as well |
| `@governance` | Catalog and model-provider policy — the operator-facing surface Langflow 1.12 ships in **OSS**, not only in Enterprise: `catalog-policy/*`, `model-provider-policy`, `policy-bundle{,/history,/rollback}`. Measured on `1.12.0.dev32` against an EE build of `release-1.12.0` — 25 of EE's 55 governance routes are in the nightly and the blocks are *enforced*; `sso/*`, `authz/status|check|admin/*`, `enterprise-admin/*`, the admin UI and env-declared policy are the EE-only remainder. Always combined with `@destructive`: the policy is instance-global, so a blocked component is blocked for every worker sharing that Langflow. **RBAC is out of scope** — the OSS authorization service is pass-through (`enforce()` returns True and says so in the log), so a role-restriction assert would assert nothing |
| `@integrations` | **Dedicated Integrations** (upstream epic LE-2398, Langflow 1.13) — the `Connection` entity (`/api/v1/connections` and its OAuth sub-routes), the capability manifest and effective policy (`/api/v1/integrations{,/policy/effective}`), the `/settings/connections` page, and whether the connector components the manifest promises are reachable. A **new** functional tag rather than a reused one, by the same rule as `@authz`: `@settings` covers that page as navigation, not the connection contract; `@components` is canvas/sidebar configuration; and `@model-provider` is a different entity with a different store — upstream states connections must **not** appear in `/settings/global-variables`, which is where every provider credential lands today. Not a lane selector: measured on `1.13.0.dev19`, the whole surface is served by the OSS nightly with no env var and no second instance, and the `ENABLE_INTEGRATIONS` gate its own upstream design declares (`design/dedicated-integrations/frontend-surfaces.md`, surface A9) is wired nowhere — no flag in the frontend bundle, no key in `GET /api/v1/config`. The credential harness needs no OAuth app: `ConnectionCreate` accepts a `credentials` object, so a planted token reaches `status: ready` and the specs assert the secret boundary against it (#1966–#1971). The OAuth routes need no tenant either: every lane and starter sets `LANGFLOW_CONNECTION_OAUTH_REGISTRATIONS` to eight **fake** registrations, one per OAuth provider and Slack profile (`scripts/lib/fake-oauth-registrations.json`, every copy pinned by `scripts/fake-oauth-registrations.test.mjs`), which reach `oauth/start` and a denied callback without calling any provider — decision and measurements in `docs/api/connections/oauth-fake-registrations.md` (#2301); `'{}'` reproduces the product default. Jira, Confluence, Salesforce and ServiceNow also need the **deployment site** their registration is bound to, so the same lanes and starters set four fake sites (`LANGFLOW_JIRA_CLOUD_ID`, `LANGFLOW_CONFLUENCE_CLOUD_ID`, `LANGFLOW_SALESFORCE_ORIGIN`, `LANGFLOW_SERVICENOW_ORIGIN`; `scripts/lib/fake-integration-sites.json`, #2498) — without one the server drops that registration from the list and says nothing |
