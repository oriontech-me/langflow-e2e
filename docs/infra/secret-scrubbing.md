# Secret scrubbing in published reports

> Moved verbatim from `CLAUDE.md` (#2532). `CLAUDE.md` keeps the standing rules and links here; this file keeps the mechanism, its history and its measurements. Counts and dates are as of when each passage was written. Re-measure before quoting one.

- **Secrets are scrubbed from every published report (#2486)** — Playwright redacts nothing: a trace records each `APIRequestContext` request with its headers and body (the `request` fixture and `playwright.request.newContext()` alike) and the text of every `fill()`, password inputs included, and the HTML report embeds error messages whose call log prints request headers (#2485). So a provider key reaches the report through a probe's header, a variable write's body, the frontend's own POST when a spec saves the key in the UI, and the field it is typed into; moving one route to Node `fetch` closes that route only. On 2026-11-18, **56 of 91** live artifacts of this PUBLIC repository carried provider keys, most of them in the report data rather than in a trace, and were deleted. `scripts/scrub-secrets.mjs` removes the VALUES (not a key shape, which misses Azure) of every variable named like a credential (`_KEY`, `_TOKEN`, `_SECRET`, `PASSWORD`…, optionally with a `_N` suffix; configuration kept as a secret, such as a deployment name that is also a model id, is left alone because it appears in test titles) from every text file, every zip entry at any depth and the base64 zip `index.html` embeds. Each value is searched as given, trimmed, JSON-escaped, as its UTF-8 bytes, with colour codes between any two characters (Playwright's assertion diff splits a key that way, and `build-run-payload.mjs` strips the codes and rejoins it), percent-encoded, and as base64 at each byte alignment (Playwright stores an inline attachment body that way in `results.json` and the blob's `report.jsonl`). A second pass then re-runs the same search and fails on any residue, as does an unreadable zip or a value stored in a binary file; it uses the same matcher, so it cannot catch a form the first pass does not know. On Actions every upload of a report, blob, `results.json` or `test-results/` runs only after a scrub step fed `${{ toJSON(secrets) }}` succeeded (`--require-secrets`, since that JSON always carries the run's token and an empty set is a wiring fault), pinned by `scripts/scrub-secrets-wiring.test.mjs`, which walks every workflow and composite action (a disabled one kept as the way back included) and evaluates each upload's `if:`; the VM scrubs in `phase_merge`, right after the merge and before the guards, the payload, the umbrella and the history row read the files, and `phase_publish` withholds the evidence when that did not verify. Both lanes scrub `results.json` FIRST and in its own run: its readers run whatever the scrub's outcome, so a crash on the much larger report must not leave it dirty. What it cannot reach: a key typed into a plain-text field is visible in a screenshot or video, which it does not rewrite; a token Langflow mints during the run is not known to it; and a form not listed above. The flag is `--dotenv`, not `--env-file`: Node 20 parses the latter as its own option even after the script name.
