# `manual.yml`, lane services and shared lane helpers

> Moved verbatim from `CLAUDE.md` (#2532). `CLAUDE.md` keeps the standing rules and links here; this file keeps the mechanism, its history and its measurements. Counts and dates are as of when each passage was written. Re-measure before quoting one.

- **`manual.yml`** — Parameterized manual run; accepts a Docker tag or full URL, a specific test suite, and an optional grep filter. Two further inputs exist for the **#1187 adoption gate** and only that: `any_completion_provider: ollama` routes every spec declaring `tier: "any-completion"` to this job's keyless Ollama service (no key, no quota — the resilience answer to a drained account), and `retries` lets a dispatch measure a candidate with retries off. **The gate is a measured RATE over a stated N, not *passes 3/3*** — that wording shipped with #1212 and was refuted by the first thing it certified: the pilot `agent-system-prompt` measures ~60 % routed (9/15, CI and a dev box agreeing), and at p=0.60 a three-run gate certifies with probability ≈22 %, so it did. No feasible N/N fixes it (~59 consecutive passes for 95 % confidence in p ≥ 0.95), which is why the criterion moved from counting runs to **dependence**: `any-completion` means no assertion depends on the model *choosing or managing* to do anything, and that includes timing — `agent-component-regression` passed 5/5 routed and is still `tool-calling`, because its Stop-button test needs the run to still be in flight and its interaction suite needs three turns (one long-form) inside the 5-minute cap on a model `ollama-provider.spec.ts` measures at >100 s per call on a runner. Evidence must also be the **spec on the lane**: the same 1B complies 10/10 called directly and 60 % through the Agent, so a model-alone probe measures a different system (#1187). Both are set as **job-level** `env`, because `.github/actions/run-e2e` declares per-step `env` that ADDS to the job environment rather than replacing it — the same path the three `OLLAMA_*` vars already take, so the shared action is untouched. The **external-URL** job **fails** when routing is requested instead of ignoring it: that target is not on the runner's network, so it cannot reach the service container, and honouring the input silently would run the routed specs on a hosted provider while the dispatch summary said `ollama` (#1012's rule). A third input, `provider`, makes this **the only lane that can still run multi-provider** (#1186): `auto` (default) keeps one model per active provider, `openai` / `anthropic` / `google` pin to that provider's **settled** model, and `all-models` sweeps the whole catalog — resolved by `scripts/select-manual-model-target.mjs`, never by inline `env:`, because `MODEL_TEST_PROVIDER` alone *widens* the run to that provider's entire catalog and a hardcoded id skips silently the day CI loses access (#1169's two traps). It exists because multi-provider used to be the default **by omission** and both scheduled lanes have since opted out — `pr-validation.yml` pins openai (#1169), `daily-stable.yml` rotates by weekday (#1185) — leaving no lane that runs it and no input to ask for one. **The rotation's window is wider than #1185 recorded:** "≤3 days" was the intra-week gap, but the cron is Mon–Fri, and since #2287 the week is an explicit table (Mon openai · Tue anthropic · Wed google · Thu azure-ai-foundry · Fri anthropic), so the real per-provider latency is ≤4 days for anthropic and **≤7 days** for every provider owning one weekday — google among them, the provider of #963. Those are best cases, not bounds: the rotation advances past an inactive provider, so a Wednesday with a dry google key costs google its whole week. Hence the recorded cadence: one `provider=auto` + `test_tag=@stable` dispatch per Langflow release-candidate cycle, **≥2 business days before sign-off**, owned by whoever signs the release validation, plus ad-hoc `provider=<x>` dispatches when triaging a provider-specific red. **Failure semantics deliberately differ from the two sibling lanes**, and reading them as the same will look like an inconsistency: there the pin is an optimisation the lane applies to itself, so it declines and falls back to the costlier multi-provider run (#980 — losing a scheduled day costs more than spend); here the input **is** the request, so a selection that cannot be honoured **exits 1** with the cause named (no `continue-on-error`), because continuing would run the other providers, answer a different question and report success. This lane is never scheduled, so that costs a re-dispatch, not coverage. `auto` emits nothing and no state of the catalog can fail it, which is what makes "the default is unchanged" a property rather than a promise — **but it is not silent, and that distinction is the point:** `collect-models` writes `models.json` only at the *end* of its sweep and is `continue-on-error` here, and with no catalog `resolveTestTargets()` returns **one** `provider:openai (fallback)` target whose `skipReason` is `undefined` (the health map is empty on an absent `providers.json`), while openai's key *is* forwarded — so ~30 parametrized agent tests would run one provider, green, under a log line promising multi-provider. `auto` therefore reads the catalog for reporting only, prints the fan-out it derived from it, and warns when that fan-out is not multi-provider. **It reads `providers.json` too, and that is the likelier of the two failures:** the resolver takes its targets from `models.json` and then attaches `providerSkipReasons()` from `providers.json`, so a provider the probe recorded `inactive` still yields a target — one that `test.skip()`s — and the two files disagree by construction, since `collectAll()` scrapes the model lists in step 2 and validates the keys only in step 3 (`models.json` mirrors the Langflow catalog, not the validation; a capped Google key left all 36 google models in it, #1029). Counting the catalog printed *"Resolves 3 target(s)"* for a dispatch where two of the three skipped — the same overstatement as the absent-catalog case, by the route this account has actually been down four times (#772 and #1450 openai, #1029 google, #1169 anthropic) — so the count, the warning and the printed line are all over the **runnable** targets, with the skipped ones named alongside the reason `collect-models` recorded. Reading the health file is **fail-open**, mirroring `readProviderHealth()`: absent or unparseable means no signal, nothing skips, so those targets count as runnable and the unverified fan-out is warned about rather than assumed dead. One more thing only this lane can hit: `any_completion_provider` and `provider` can both be set, and routing **outranks** the pin for `tier: "any-completion"` (#1187) — the specs announce that themselves but only mid-run, so the step announces it at dispatch time. `all-models` declines outright when `models.json` is absent or empty, since `ALL_MODELS=true` over an empty catalog resolves one `(fallback)` target per spec — the opposite of the sweep, logged as a success — and when it does sweep it announces the size **and** that an unnarrowed sweep will not finish inside the job's timeout — **without naming the cap**, which is what let the previous wording sit green at "90-minute" after #1174 raised the job to 180, pinned by an assertion that the warning carries no `\d+-minute` at all. The **external-URL** job rejects any selection but `auto` for the same reason it rejects `ollama` routing: it runs no `Collect models` (that would write our keys into an instance we do not own, #1055) and receives no provider key, so every parametrized LLM spec skips there regardless and honouring the input would produce the green all-skip #570/#1012 exist to prevent. **What `manual.yml` can actually run** (#1174). It is unsharded, 2 workers, one backend — the same **workers-per-backend ratio** as a single `daily-stable` shard, so the daily's own numbers are the estimate rather than a scaling argument. The `@stable` selection summed across the four shards measured **55.4 / 56.9 / 64.2 / 140.3 min** of test time on four runs between 2026-09-01 and 09-03, against ~5.4 min median fixed overhead (a real dispatch, run 32982297663, measures 5.47). **Read that transfer as a floor, not an equivalence** — it is optimistic on three axes, and the first is the one this repo documents as decisive: `manual.yml` is the **only** E2E lane that does not pin `LANGFLOW_WORKERS: "1"` (nor `LANGFLOW_WORKER_TIMEOUT`), so its backend runs gunicorn's `(2*cpu)+1` — the condition behind the four-shard wedge in run 30351107916 (#773/#1011), where a wedge then costs the 300 s default instead of 120 s; the daily shards run inside the Playwright container while this lane pays `setup-playwright`; and the daily sets `PW_SHARD_FILE_LEVEL=1` (`fullyParallel: false`) where this lane leaves it true. The **140.3 tail is itself a broken build** — all four shards of that run were red, and `retries: 2` amplifies a red run's duration — which is still the right case to size for, since a reviewer dispatches a suite-wide verification precisely when something may be failing. **The full suite is not a selection this lane can finish, and no timeout fixes that**: of the **298** regression specs, **209** carry `@stable`, **32** are lane-gated (`@destructive` / `@enterprise` / `@serving` — `playwright.config.ts` `grepInvert`s the first where a CLI `--grep` cannot override it, and the other two need a different instance, so no dispatch here reaches them **at all**), and the remaining **57** are the validation backlog: non-`@stable` precisely because they are broken or blocked on a known product bug, each retrying **twice** against a 5-minute per-test timeout, so a handful of timeouts alone costs 45 minutes. `test_tag=@stable` is therefore the bound the PR warning names, and `timeout-minutes` is **180**, not 90 — 90 sat *inside* the measured spread rather than above it, so one dispatch in that sample would have been killed partway and returned no merged report at all, which is the whole cost: a run that bills its full runtime and yields nothing. `TOKENS_MAX_SECONDS` tracks that timeout (**10500**) — left at 5100 it would stop recording 85 minutes into exactly the long dispatches the raise exists to allow. **Two things the original framing got wrong, worth not re-deriving:** tag slicing does not reach the suite because **104 of 298** specs carry no functional tag at all (63 of them `@stable`) — not the 2 that #1174 named, which were the leftovers of one PR's diff; and **no spec is untagged**, so every spec *is* reachable by some tag, just never by the `@components` / `@playground` / `@agents` slicing used as the workaround.

- **Local Ollama (`ollama-e2e`)** — `ollama-provider.spec.ts` needs a live Ollama with a known model. The lanes start `ghcr.io/<repo>/ollama-e2e:llama3.2-1b`, our own image (`docker/ollama-e2e/Dockerfile`, #583) with the weights **baked in** so no run pays a 1.3 GB pull from `registry.ollama.ai` mid-lane, and set three variables the spec reads: `OLLAMA_BASE_URL` (probed from the test host), `OLLAMA_BASE_URL_FROM_LANGFLOW` (typed into Langflow, so it goes through the SSRF layer) and `OLLAMA_TEST_MODEL`. **The QA VMs have no container to run it in**, so `scripts/start-ollama-source.sh` serves the same pinned release natively — the base tag in that Dockerfile is pinned and a unit test reads both the version and the model out of it, so the container and the native path cannot drift apart. The native path binds an RFC-1918 address (loopback is blocked by the SSRF layer whatever the allowlist says) and treats a **missing model as a failure**, because the spec's own response to one is to skip — a green lane one test short, the same failure shape as the echo's public-address case.

- **Self-hosted echo endpoint (`go-httpbin`)** — Every lane that runs echo-dependent specs (API Request component, the agent fetch-tool specs) starts a `ghcr.io/mccutchen/go-httpbin` service container and resolves `ECHO_BASE_URL` to it via `.github/actions/resolve-echo-endpoint`, so those specs never call the public internet. Built for `daily-stable.yml` (#462/#639) and extended to `pr-validation.yml`, `nightly.yml` and `manual.yml` in **#1128**, after PR #1133 lost three specs to an `httpbin.org` 504 that read like a product failure. Two things make this non-obvious and are encoded in the action: Langflow's `validators.url()` **rejects a single-label host**, so the variable must be a raw container IP (never `http://go-httpbin:8080`), and its SSRF layer blocks private addresses unless the RFC-1918 CIDRs are in `LANGFLOW_SSRF_ALLOWED_HOSTS` and blocks loopback outright — so the address the **job probes** (`localhost:<mapped port>`, on host-based lanes) is not the address **Langflow calls**. The failure mode differs by lane on purpose: `mode: fail` on PR/nightly/manual, because a silent fallback to the public host is what made #1128 look like a product bug, and `mode: warn` on the daily, where a day of coverage outweighs strictness (same reasoning as `Collect models`, #980). The decision logic lives in `scripts/resolve-echo-endpoint.mjs` and is covered by `npm run test:scripts`. **The QA VMs have no container to run it in**, so `scripts/start-echo-source.sh` runs the *same pinned binary* natively and `--topology native` decides its address — where the rule tightens: a public address is a **warning** under a container (it risks a 400 that names itself) and, natively, a **refusal on a lane that asked to fail**, because `privateEchoEndpoint()` *skips* an admitted-case assertion whose host Langflow does not block by default, so the SSRF spec would stop asserting and the lane would still report success. A host that carries a public address alongside the private one makes that one interface-ordering away. **The severity is `mode`'s to decide and never the topology's**, and reading it as "native always refuses" gets two things wrong. Under `warn` the native path resolves the **local** public address instead of refusing, because leaving `ECHO_BASE_URL` unset loses the same assertion *and* puts every other echo spec on public httpbin.org (#1128) — the strictly worse of the two, and the shape the first version of this tolerated in one branch while refusing it in the other. The exception is an address Langflow blocks **by default** (loopback, CGNAT, link-local): resolving one answers 400 on every echo spec, so `warn` leaves it unset and says so. And under `warn` the native path returns **no error at all**, which is what keeps the verdict caller-proof — the shared action short-circuits any not-ok decision to `exit 0` when `mode: warn` without reading `error`, and the native caller is hand-written shell on the mirror (a composite action only runs inside Actions, and these machines have no runner), so that idiom is what gets copied. An `error` therefore implies `--mode fail`, pinned by a property test rather than by this sentence. `manual.yml`'s **external-URL** job is scoped out — it targets a Langflow that is not on the runner's network and cannot reach a service container.

- **Post-collect-models health gate (`.github/actions/wait-for-backend`)** — Every lane that shares one Langflow container between its `Collect models` sweep and its test run polls `/api/v1/version` between the two, through this one action: `pr-validation.yml` and `manual.yml` (and `daily-stable.yml`, disabled since 2026-10-02; the VM daily has its own gate in `scripts/run-e2e.sh`). The sweep can leave the backend process-wide **wedged** (container alive, healthcheck green, event loop blocked — #922/#927); `globalSetup` polls 120 s and then throws, so a wedge that outlasts that window costs the whole lane and reports itself as an unattributed preflight timeout. The gate buys two things: a longer window for the wedge to clear (recovery is real and measured — 223 s on #1019, 260 s on #1044's dispatch, every second of it gunicorn's own `WORKER TIMEOUT` → `SIGKILL` → ~12 s restart), and, when it does not clear, **attribution** — its `::error::` names which state it observed (refused → dead; accepted-and-unanswered → the wedge; non-2xx → an application failure that is *not* the wedge), unconditionally, on every run. It was three copy-pasted shell loops until **#1045** (`#1011` daily → `#1019/#1044` pr-validation → `manual.yml`) and they had already diverged on the deadline, the heartbeat and the attribution, while `weekly-stable.yml` — the documented fallback — had no gate at all. One deadline now: **420 s** for every lane, over-waiting being nearly free because the extra time is only ever spent on a lane already headed for a red. The loop lives in `scripts/wait-for-backend.mjs`, exercised by `npm run test:scripts` against all four backend states (healthy / dead / wedged / wedged-then-recovers) plus a structural guard that the gate still sits between `Collect models` and the run step in all four workflows — the wedge itself cannot be reproduced on demand, since it depends on the runner's collect-models load. A failed sweep is surfaced here as a `::warning::` and never gates the run (#980/#570).

- **`--grep` composition (`scripts/build-grep-filter.mjs`)** — Playwright honours exactly **one** `--grep`, so a lane wanting "tag AND name" — or "`@destructive` AND whatever the dispatch asked for" — has to AND its filters itself as a lookahead chain. Four lanes did that inline, interpolating each fragment **unparenthesised** (`--grep "(?=.*${TEST_TAG})(?=.*${TEST_GREP})"`), and alternation has the lowest precedence inside a group — so a fragment containing `|` did not go in as a unit. `test_tag=@stable` with `test_grep=@agents|@model-provider` selected **48 tests / 26 files where the correct filter selects 81 / 37**, byte-identical to asking for `@agents` alone: the dispatch was accepted, the job was green-path, and nothing in the log or the summary said the run was narrower than requested (#1012's rule). It cost real coverage during the 1.11.2rc3 release validation (#1275). **The mechanism is positional, and the obvious reading of it is wrong in a way that decides whether a test fixture can catch it.** Lookaheads are zero-width, so every lookahead in the chain is evaluated at the **same** starting position and the engine may try any position — a `.*`-prefixed branch is position-insensitive, a bare branch like `@model-provider` pins the start to where that token begins, and every other lookahead must then match from there onward. The broken filter therefore asked *"@model-provider appears, AND @stable appears at or after it"*, unsatisfiable here only because `@stable` is declared **first** in essentially every `tag:` array (55 specs are `["@stable", "@regression", "@components"]`). So the defect is **order dependent**: the same bug leaves the selection accidentally correct whenever the alternated token happens to come first, and a fixture using that ordering **passes against the bug** — which is why the tests assert both orderings. Fixing it in the YAML was one character per side, and rejected for that reason: the only available guard would be a regex over the workflow text, and #1226 established that such a guard passes the mutations it exists to catch. The composition lives in the script so `npm run test:scripts` covers it by **selection** — each case compiles the composed filter and runs it against real suite titles (reverting the wrapper fails 3 of them). Four further properties it guarantees: a **single** fragment is passed **verbatim**, so the overwhelmingly common `--grep @stable` path is on exactly the string it used before; **no** fragments means no `--grep` at all rather than an empty regex, which matches every test and would turn a narrowed dispatch into a full-suite run; an invalid fragment is refused **there**, naming it, instead of reaching Playwright as a composed string whose error points at the composition (`shell: bash` runs with `-e`, so `FILTER=$(…)` failing aborts the step); and the wrapper is `(?:…)`, never `(…)`, which would renumber a backreference the caller wrote inside its own fragment. One accompanying test **is** structural, and it pins an **absence**, not a spelling: no YAML under `.github/` composes a lookahead around an interpolated variable. It cannot tell whether a lane composes correctly — the behaviour tests do that — but the bug reached four lanes by copy-paste, so a fifth is how it returns. Independently, `nightly.yml` read `test_grep` as `${{ … }}` **inside** `run:`, which the `run-e2e` action explicitly forbids for its own inputs: substitution happens before bash parses the line, so a dispatch value like `"; rm -rf` breaks out of the string — both of its steps now take it through `env`.
